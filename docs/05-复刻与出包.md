## 二、从零重建（GitHub Actions）

### 1. 建仓库

GitHub 上新建空仓库（不要勾 README / gitignore），比如 `rd-dylib`。

### 2. 本地初始化并推送

```bash
cd E:\zm\dylib
git init
git config user.name "你的名字"
git config user.email "你的邮箱"
git add -A
git commit -m "init"
git remote add origin https://github.com/<用户名>/rd-dylib.git
git push -u origin master:main
```

> 推送要认证。用 token 的话注意：`.git/config` 里会留下明文 token，
> 交接或分享前记得清理（`git remote set-url origin <无 token 的地址>`）。
>
> 如果这台机器要过代理，见坑 9：
> ```bash
> git -c http.proxy=http://127.0.0.1:7897 -c http.sslVerify=false push -u origin master:main
> ```

### 3. 等 CI

推上去自动触发。约 40 秒出包。

**必须用 `macos-15-intel`**（`macos-14` 会解析成 arm64 runner 被拒，见坑 1）：

```yaml
jobs:
  build:
    runs-on: macos-15-intel
```

### 4. 下载产物

网页：仓库 → Actions → 最新 run → 页面底部 Artifacts → `RemoteDebug-dylib`。

命令行（需要 token）：

```bash
# 取 artifact id
curl -sk -H "Authorization: Bearer <TOKEN>" \
  "https://api.github.com/repos/<owner>/<repo>/actions/runs/<RUN_ID>/artifacts"

# 下载
curl -skL -H "Authorization: Bearer <TOKEN>" \
  "https://api.github.com/repos/<owner>/<repo>/actions/artifacts/<ARTIFACT_ID>/zip" \
  -o art.zip

# 解压出 RemoteDebug.dylib，放到 dist/
```

## 三、编译命令详解

CI 里跑的就是这一条（`build.sh` 同款）：

```bash
SDK=$(xcrun --sdk iphoneos --show-sdk-path)

xcrun --sdk iphoneos clang \
  -arch arm64 \
  -miphoneos-version-min=14.0 \
  -isysroot "$SDK" \
  -dynamiclib \
  -fobjc-arc \
  -O2 -Wall \
  -Wno-unused-function \
  -Wno-arc-retain-cycles \
  -install_name @executable_path/RemoteDebug.dylib \
  -framework Foundation \
  -framework UIKit \
  -framework JavaScriptCore \
  -framework AudioToolbox \
  -framework CoreGraphics \
  -framework CoreFoundation \
  -o build/RemoteDebug.dylib \
  src/RemoteDebug.m src/RDIndexHTML.m src/RDHook.m \
  src/RDAutomation.m src/RDTool.m src/RDFloat.m
```

### 每个参数为什么

| 参数 | 作用 |
|---|---|
| `-arch arm64` | 只要 arm64，iPhone 14 Pro 用户态就是 arm64 |
| `-miphoneos-version-min=14.0` | 最低 iOS 14 |
| `-dynamiclib` | 产出 dylib（filetype=6） |
| `-fobjc-arc` | ARC。代码里大量 block 依赖它 |
| `-install_name @executable_path/RemoteDebug.dylib` | **关键**。dylib 放在 .app 根目录，用 exe 相对路径引用 |
| `-framework JavaScriptCore` | `/api/eval` 靠它 |
| `-framework AudioToolbox` | `device.vibrate` 的 `AudioServicesPlaySystemSound` |
| `-framework CoreGraphics` | `CGRectGetMidX/CGRectGetMidY/CGRectIsEmpty/CGRectZero/CGSizeZero`，UIKit 不会自动带进来，**漏了必报 undefined symbols** |
| `-framework CoreFoundation` | `CFRelease` / `kCFAllocatorDefault` |
| `-Wno-arc-retain-cycles` | hook 规则和它的 block 互相强引用是**故意的**（规则要常驻） |

**不需要链接 IOKit**。触摸注入用 `dlopen` + `dlsym` 动态取符号，拿不到就降级，
不会因为某个系统版本缺符号而加载失败。

## 四、注入

### 方式 A：TrollFools（推荐）

1. 把 `RemoteDebug.dylib` 传到手机（AirDrop / 微信 / 文件 App）
2. TrollFools 里选目标 app → 注入 → 选这个 dylib
3. 杀掉 app 重开

**换版本时**：先在 TrollFools 里把旧的删掉，再注入新的。直接覆盖有时会残留两个。

### 方式 B：改 IPA

```bash
python tools/inject_ipa.py 你的.ipa -d dist/RemoteDebug.dylib -o 你的-debug.ipa
```

先看空间够不够：

```bash
python tools/inject_ipa.py 你的.ipa --check
```

输出里「可用 padding」大于 200 字节就行。不够就退回方式 A。

改完的包用 **TrollStore 安装**（它会二次签名，别用别的签名工具）。

## 五、换一个目标 app

1. 改 `RemoteDebug/src/RemoteDebug.m` 顶部的端口（可选，默认 8899）
2. 不需要改任何 bundle id 相关的东西 —— 代码里全部用 `[NSBundle mainBundle]`
3. 重新出包、注入新 app
4. 跑 `python tools/selftest.py <新IP>`

日志目录会自动变成新 app 的容器（`Documents/RemoteDebug/`），
不用手动清理。

## 六、编译错误对照表

| 报错 | 原因 | 解法 |
|---|---|---|
| `use of undeclared identifier 'x'` + `incompatible block pointer types` | `id (^b)(NSString *) = ^id{...}` —— `^id{}` 是无参 block | 写成 `^id(NSString *nm){...}` |
| `Undefined symbols: _CGRectGetMidX` 等 | 漏了 `-framework CoreGraphics` | 补上 |
| `Undefined symbols: _CFRelease` | 漏了 `-framework CoreFoundation` | 补上 |
| `Undefined symbols: _AudioServicesPlaySystemSound` | 漏了 `-framework AudioToolbox` | 补上 |
| `warning: capturing 'r' strongly ... retain cycle` | 有意为之 | 加 `-Wno-arc-retain-cycles` |
| `error: address of property expression...` | ARC 下对 `id` 取地址 | 用 `__unsafe_unretained id` |
| `cast of Objective-C pointer to integer` | ARC 下 `(intptr_t)obj` 非法 | 用 `(intptr_t)(__bridge void *)obj` |
