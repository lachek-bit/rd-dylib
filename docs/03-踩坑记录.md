## 坑 1：CI 一推就被取消，2 秒结束，零 step

**症状**

GitHub Actions 里 run 显示 `cancelled`，总时长 1~2 秒，job 一个 step 都没跑。
网页上的报错文案：

```
不支撑配置 macos-14-arm64-us-default
```

**原因**

`runs-on: macos-14` 在 2025 年之后默认解析成 **arm64** macOS runner
（完整标签 `macos-14-arm64-us-default`）。这个账号用不了 arm64 的 macOS runner，
被直接拒绝。

**解法**

```yaml
runs-on: macos-15-intel     # 换成 Intel 版
```

`macos-13` 已经 EOL，不要用。

**怎么快速判断**：run 是 `cancelled` + 零 step + 2 秒 = runner 分配失败，
不是你的 YAML 语法问题。点进 run 页面看 Annotations 就有那句中文提示。

## 坑 2：`/api/classes` 必崩（三个版本才修对）

**症状**

调 `/api/classes?q=Grow`，连接直接被断开（`RemoteDisconnected`），
之后所有请求都是「连接被积极拒绝」—— 进程死了。app 闪退。

**三次错误归因（前两次都是我猜错的，别重复）**

1. 第一次怪「`@(cString)` 遇到非法 UTF-8 返回 nil，`addObject:nil` 抛异常」→
   加了 nil 兜底和 `@try`，**没用**。
2. 第二次怪「`objc_getClassList` 第二次返回实际总数，可能大于 buffer 容量，
   `buf[i]` 越界读」→ 加了夹取，**还是崩**。
3. 第三次拿到 crash.log 才定案。

**真正的崩溃栈**

```
signal=11 (SIGSEGV)  addr=0x0
3   libswiftCore.dylib    swift_getSingletonMetadata + 880
8   libobjc.A.dylib       objc_getClassList + 80
9   RemoteDebug.dylib     RDAllClassNames + 36
10  RemoteDebug.dylib     RDHandle + 7620
```

**原因**

在 Swift app 里，某些类的元数据是**懒加载**的。`objc_getClassList` 内部会调
`class_getName`，而 `class_getName` 会触发 `swift_getSingletonMetadata` 去实例化
元数据 —— 如果这个类正处于半初始化状态（Swift 运行时还在注册），直接 SIGSEGV。
`objc_copyClassList` 也一样（它内部同样走 class_getName）。

**解法**

完全不碰 Class 对象，只读名字字符串：

```objc
unsigned int imgCount = 0;
const char **images = objc_copyImageNames(&imgCount);
for (unsigned int i = 0; i < imgCount; i++) {
    unsigned int clsCount = 0;
    const char **names = objc_copyClassNamesForImage(images[i], &clsCount);
    // names[j] 是 const char *，直接转 NSString，元数据永远不被触发
    for (...) { NSString *s = [NSString stringWithUTF8String:names[j]]; ... }
    free(names);
}
free(images);
```

另外加 15 秒缓存，减少重复开销。

**铁律**：在 Swift app 里，**任何可能触发类元数据实例化的 API 都是雷**
（`objc_getClassList` / `objc_copyClassList` / `class_getName` 全中）。

**如果还要更保险**：直接砍掉这个接口。`/api/methods?cls=已知类名` 不崩，
够用了 —— 类名可以从 UI 层级里拿到（`Grow.xxx` 这种前缀很好认）。

## 坑 3：悬浮球加了之后整屏点不动（不是死锁）

**症状**

app 正常启动、界面都在、日志正常打、`/api/eval` 0.15 秒就响应 ——
**主线程完全健康**，但屏幕上点哪儿都没反应，像卡死。

**原因**

悬浮球最初用了一个**独立的全屏透明 UIWindow**（`windowLevel = Alert + 200`）。

iOS 在 window 之间**不做 hitTest 穿透**：系统按 windowLevel 选中顶层 window，
只在这个 window 内部 hitTest，返回 nil 就把事件**丢弃**，不会传给下面的 app window。
所以那个透明 window 把整屏触摸全吃了。

**解法**

不要独立 window。把浮层作为「空白处穿透」的普通视图挂到 **app 自己的 keyWindow**
最上层：

```objc
@interface RDPassthroughView : UIView
@end
@implementation RDPassthroughView
- (UIView *)hitTest:(CGPoint)point withEvent:(UIEvent *)event {
    UIView *v = [super hitTest:point withEvent:event];
    return (v == self) ? nil : v;   // 空白处返回 nil，同一个 window 内会继续问下一个兄弟视图
}
@end

[window addSubview:host];   // host 是 RDPassthroughView
```

再加一个每秒一次的 `bringSubviewToFront`，防止 app 切页面时把它盖住。

**怎么区分「死锁」和「吃触摸」**：调 `/api/eval` 发个最简单表达式。
能秒回 = 主线程没死 = 是触摸问题。

## 坑 4：悬浮球点一下没反应（只有 pan 手势）

**症状**

悬浮球显示出来了，能拖动，但**点一下什么都不发生**（不复制地址、不弹提示）。

**原因**

只加了 `UIPanGestureRecognizer`，然后想在 pan 的 `Ended` 状态里判断位移小于
阈值就当点击。

问题：**`UIPanGestureRecognizer` 有约 10pt 的最小移动阈值，纯点击根本不会进入
`Began` 状态**，handler 压根不会被调用。

**解法**

单独挂一个 tap：

```objc
UITapGestureRecognizer *tap =
    [[UITapGestureRecognizer alloc] initWithTarget:ctrl action:@selector(onTap:)];
[btn addGestureRecognizer:tap];

UIPanGestureRecognizer *pan = ...;
[pan requireGestureRecognizerToFail:tap];   // 拖动时不触发点击
[btn addGestureRecognizer:pan];
```

并把 pan 里「判断点击」那段删掉，避免双触发。

## 坑 5：hook 一装，app 就进入崩溃循环

**症状**

装了 `NSUserDefaults boolForKey:` 的 hook（`mode=log`），app 立刻崩。
**重开还是崩**，因为 hook 被写进了 `hooks.json`，每次启动自动装回去。

**原因**

两个错误叠在一起：

1. **hook 默认落盘**。调试期的实验性 hook 被持久化，重启后自动重装。
2. **没有崩溃循环检测**。崩了之后没有人把危险规则摘掉。

**解法（三层）**

1. **规则版本迁移**：`hooks.json` 里每条规则写 `"v": 2`，加载时
   `if (![item[@"v"] isEqual:@2]) continue;` —— 旧规则自动失效。
2. **boot 标记**：启动写 `booting` 文件，20 秒后删。下次启动发现还在 →
   判定上次启动后 20 秒内崩了 → 把 `hooks.json` 移到 `.bad`，跳过恢复。
3. **默认不落盘**：`/api/hook` 要显式 `persist=1` 才写盘。调试期的 hook
   重启即失效，最安全。

**额外教训**：**hook 系统核心类风险极高**。`NSUserDefaults` 是 toll-free bridged
的 CFPreferences，内部有绕过 ObjC 消息发送的路径，替换它的 IMP 容易出问题。
优先 hook 业务类，别碰 Foundation / CoreFoundation 的核心方法。

## 坑 6：日志和配置写不到 `/var/mobile/Library`

**症状**

按设计把 `hooks.json` / `last.log` 写到
`/var/mobile/Library/RemoteDebug/<bundleid>/`，结果目录能创建（返回成功），
但文件读不到 / `createDirectoryAtPath` 实际失败后静默降级。

**原因**

TrollStore 注入的 dylib **没有 `com.apple.private.security.no-sandbox`
entitlement**，仍然受 app 沙盒约束。`/var/mobile/Library` 不在自己容器内，写不了。

**解法**

退回沙盒内 `NSHomeDirectory()/Documents/RemoteDebug/`。代码里做了自动降级：

```objc
NSString *global = [NSString stringWithFormat:@"/var/mobile/Library/RemoteDebug/%@", bid];
if ([fm createDirectoryAtPath:global ... error:&e]) dir = global;
else dir = [NSHomeDirectory() stringByAppendingPathComponent:@"Documents/RemoteDebug"];
```

**后果**：路径带容器 UUID，**每次重装 app 都会变**，见坑 7。

## 坑 7：容器 UUID 每次重装都变，路径不能硬编码

**症状**

自检脚本里硬编码了
`/var/mobile/Containers/Data/Application/1627E39C-.../Documents/RemoteDebug/last.log`，
重装一次后「读日志」两项就 FAIL，但文件其实好好的。

**原因**

`NSHomeDirectory()` 返回的路径里有容器 UUID，重装 / 重新签名后会换。

**解法**

先取 `/api/info` 的 `home` 字段，再拼路径：

```python
_, raw, _, _ = call("/api/info")
home = (jload(raw) or {}).get("home", "")
check("读 last.log", "/api/file?path=%s/Documents/RemoteDebug/last.log" % home)
```

或者直接调 `app.paths` 工具，它返回 `data_dir` / `home` / `bundle`。

## 坑 8：`/api/defaults` 抛异常而不是返回错误

**症状**

```json
{"error":"NSInvalidArgumentException: Invalid type in JSON write (__NSCFData)","ok":false}
```

**原因**

`NSUserDefaults dictionaryRepresentation` 里混着 `NSData`（token、缓存），
`NSJSONSerialization dataWithJSONObject:` 遇到会**直接抛 ObjC 异常**，不是返回
nil + error。我原来写的 `if (!jd) { 降级 }` 分支永远进不去。

**解法**

遍历字典，把不可序列化的值换成说明文本，再序列化：

```objc
if ([v isKindOfClass:[NSData class]]) {
    clean[k] = [NSString stringWithFormat:@"<data %lu bytes>", (unsigned long)[(NSData *)v length]];
} else if ([v isKindOfClass:[NSDate class]]) {
    clean[k] = [NSString stringWithFormat:@"<date %.0f>", [(NSDate *)v timeIntervalSince1970]];
} else if (是 NSNumber/NSString/NSArray/NSDictionary) {
    clean[k] = v;
}
```

外层再套 `@try` 兜底。

**通用教训**：`NSJSONSerialization` 的 `dataWithJSONObject:` 在很多情况下**抛异常
而不是返回 nil**，凡是用它都要 `@try`。

## 坑 9：网络 —— 沙箱代理不放行 GitHub

**症状**

- `curl https://api.github.com` 返回 `000`，exit code 35（SSL error）
- `git clone` 报 `schannel: failed to receive handshake` 或
  `CONNECT tunnel failed, response 502`
- 但 `curl https://www.baidu.com` 返回 200

**原因**

执行环境注入了自己的代理 `http_proxy=http://127.0.0.1:60704`，这个代理只放行
国内域名。用户自己的梯子在 `127.0.0.1:7897`（Clash），但被环境变量覆盖了。

**解法**

```bash
# curl：清掉环境变量 + 显式指定用户的梯子 + -k（证书校验会失败）
env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY \
  curl -sk -x http://127.0.0.1:7897 https://api.github.com/

# git：proxy + sslVerify 一起关（schannel 在代理隧道下握手失败）
git -c http.proxy=http://127.0.0.1:7897 -c http.sslVerify=false clone ...
git -c http.proxy=http://127.0.0.1:7897 -c http.sslVerify=false push ...
```

**别忘了用完把 git 全局配置撤掉**：

```bash
git config --global --unset http.proxy
git config --global --unset http.sslVerify
git config --global --unset http.sslBackend
```

否则会影响用户自己以后的所有 git 操作。

**大文件下载**：GitHub release（`objects.githubusercontent.com`）在这条线路上
基本下不动（0 字节），`codeload` 只有 130 KB/s 且容易断。**不要在本地编译**，
直接走 GitHub Actions。

## 坑 10：命令行传长 JS 会被转义搞坏

**症状**

```bash
curl -X POST --data-binary "var u=_rd.call('NSUserDefaults','standardUserDefaults',[]); ..." 
```

返回 `{"ok":false,"error":"empty code"}` —— 服务端收到的 body 是空的。

**原因**

JS 里有单引号、双引号、括号、`$`、`;`，在 bash 里嵌套引号时被吃掉了。

**解法**

写文件再传：

```bash
cat > js.txt <<'EOF'
var u = _rd.call('NSUserDefaults','standardUserDefaults',[]);
_rd.inst(u,'boolForKey:',['premium'])
EOF
curl -s -X POST --data-binary @js.txt http://IP:8899/api/eval
```

`<<'EOF'` 的单引号很重要，保证内容原样写入不做变量展开。

**另一个坑**：在 bash 里定义 `G(){ curl ... "$1"; }` 然后 `G url -o file`，
`-o file` 会变成 `$2 $3` 被忽略 —— 文件根本不会写。函数要用 `"$@"`。
